# Screen matrix

Every route declared in `lib/core/router.dart` and the feature route files is
listed below. `WORKING` means the screen is pumped without overflow at both
`360x640` and `412x915` by the widget suites in `test/widget/`, and the data
path is exercised by `test_e2e/e2e_api_test.dart` where an e2e case is named.
`n/a by design` means the operation is deliberately not offered because the
record is immutable/historical or is deactivated instead of deleted.

## Notes

- No cell is left as `NOT WORKING`. Immutable audit/history records use
  `n/a by design`; people and master-data records are deactivated instead of
  deleted.
- The admin Edge Functions must be deployed for create/reset-password to work:
  `supabase functions deploy admin-create-user --project-ref <ref>` and
  `supabase functions deploy admin-reset-password --project-ref <ref>`.
  UsersScreen shows these commands on 404/network failures.
- Actions rejected by `set_user_access` / `admin-reset-password` (self edits,
  admin cross-branch edits, granting `super_admin` as admin, deactivating a
  super admin) are hidden instead of rendered as failing buttons.
- Filter dropdowns and chips default to `All` (no filter) on users, audit and
  expenses; every list shows all rows when no filter is selected.
- Layout verification is in `test/widget/layout_core_test.dart`,
  `dashboard_layout_test.dart`, `pos_layout_test.dart`,
  `admin_auth_layout_test.dart`, `customer_supplier_expense_layout_test.dart`,
  `inventory_sales_layout_test.dart`, and `purchasing_reports_layout_test.dart`.
  API verification is in `test_e2e/e2e_api_test.dart` (CI job `e2e-api`).
